## Executive summary

The repository is buildable and the current storefront checkout architecture contains strong server-side controls: guest checkout calls a service-role-only atomic RPC, prices and stock are re-read inside the database, order creation and stock movements are transactional, and payment/fulfilment RPCs include ownership and idempotency checks. The latest local Meta Pixel change is committed at `0eab378` and passes local validation.

The system is **not verified as 99% production-ready**. The most important blockers are Cloudflare deployment authorization error `10000`, five authenticated `SECURITY DEFINER` RPCs flagged by Supabase, leaked-password protection being disabled, incomplete CI coverage in the named Production Verify workflow, and incomplete evidence for live Meta Pixel/Events Manager data, Auren research freshness, catalogue integrity, and production finance reconciliation.

## Architecture and deployment

The application is a React 19 / TanStack Start application with public DailyGear routes, authenticated AlexOS routes, Supabase-backed data access, a Cloudflare Worker runtime, Workers AI binding `AI`, observability enabled, and cron triggers at `0 3 * * *` and `*/30 * * * *`. The top-level configuration uses `src/server.ts`; the prebuilt artifact uses `dist/server/wrangler.json`, `main: index.js`, `assets.directory: ../client`, and `no_bundle: true`.

GitHub has separate PR, validation, typecheck, and production-verification workflows. The current Production Verify workflow runs `npm ci`, `npm run build`, and `npm run lint`, but it does not run the full test suite or typecheck. Successful GitHub checks are therefore not deployment proof.

## Confirmed strengths

The guest checkout RPC is service-role-only and atomically validates the store, product status, confirmed availability, variant ownership, pricing, and stock before creating the customer, order, line items, stock movements, and order event. Customer payment posting is idempotent by transaction reference and checks the authenticated owner and receiving account. Fulfilment separates supplier cost from supplier cash payment and keeps delivery, advertising, and other order costs distinct. The YJ funnel now waits for both funnel data and Pixel configuration before emitting `ViewContent`, and the thank-you route guards `Purchase` by order number, value, currency, Pixel ID, and a refresh-deduplication key.
