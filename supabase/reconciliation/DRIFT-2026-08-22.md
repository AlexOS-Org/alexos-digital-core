# Supabase migration reconciliation — non-production workstream

**Branch:** `migration/reconciliation-nonprod-20260822`

**Baseline:** production `main` at `b37b576`.

## Purpose

This branch exists to reconcile the Supabase migration history mismatch without changing the production database, production migration table, application data, or live Cloudflare Worker. It is an evidence and staging branch only until the remote migration files, checksums, and schema effects are independently verified.

## Reconciliation gates

1. Export the remote migration-history rows and, where available, recover the exact remote SQL bodies through an administrative, read-only process.
2. Build a version-to-version mapping using SQL checksums, object changes, and dependency order. Do not infer equivalence from timestamps or filenames alone.
3. Reproduce the remote history on a disposable Supabase branch or local PostgreSQL instance from a clean baseline.
4. Apply the local migration set to a separate disposable target and compare tables, columns, constraints, indexes, policies, functions, triggers, enum values, and seed/reference data.
5. Classify every mismatch as equivalent/renamed, remote-only, local-only, or incompatible. Any incompatible result stops the workstream.
6. Regenerate database types only after the staged schema is accepted and run the full application validation suite.
7. Open a reviewed pull request from this branch. Production migration repair requires a separate explicit approval and a backup/rollback plan.

## Explicit safety rules

Do not run `supabase migration repair`, delete remote migration-history rows, replay old migrations against production, rename local migrations to force a match, apply the reconciliation package to production, or alter production data from this branch. The existing `supabase/reconciliation/README.md` remains the controlling procedure for the business-identity reconciliation artifacts.

## Current status

This branch contains **no production schema mutation**. It is ready for the next evidence-gathering step: obtaining the exact remote migration SQL/checksum inventory and creating a disposable comparison target.
